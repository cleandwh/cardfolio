# 개인 홈 허브 (노트20 울트라) — 전체 설계서

재무 대시보드(`finance/`), 개인 기록(`life/`), 사진, 질문·답변을 **노트20 울트라 한 대**에 모으고,
S25는 **크롬으로 접속만** 하는 구조. 과금 0원, 데이터는 내 폰 밖(외부 서비스)으로 나가지 않음.

> 실행 순서·일정은 `hub/PLAN.md`. 이 문서가 `finance/DESIGN.md`·`life/DESIGN.md`보다 우선한다. 특히 `life/DESIGN.md` 3장(LLM 연결)은 이 문서 6장으로 대체.

---

## 1. 역할 분담

| 기기 | 역할 | 저장하는 것 |
|---|---|---|
| **노트20 울트라** (허브) | 웹 서버, 데이터 원본, 사진 색인·썸네일, LLM | 재무·기록 데이터(SQLite), 사진 썸네일, 백업. 사진 원본은 SD 1TB 그대로 |
| **S25** (메인 폰) | 크롬으로 접속해서 보기·입력·질문 | 아무것도 저장 안 함 (브라우저 캐시 정도) |

S25를 가볍게 쓰는 대신, **허브가 꺼지면 아무것도 안 됨**. 그래서 7장(상시 운영·백업)이 중요하다.

## 2. 접속

```
S25 크롬 ──(Tailscale: 집 Wi-Fi든 밖의 모바일 데이터든)──▶ http://note20:8080
                                                            ├ /         홈 (요약 + 질문창)
                                                            ├ /finance/ 재무 대시보드
                                                            ├ /life/    기록 (경조사·물품·카드·메모)
                                                            ├ /photos/  사진
                                                            └ /api/...  데이터·질문 API
```

- 모든 화면과 API를 **허브 한 곳(같은 주소)에서 제공** → 앞서 걱정했던 https/http 혼합 차단 문제가 생기지 않음.
- 남는 제약: `http` 주소라 크롬이 "홈 화면에 앱 설치(PWA)"를 막을 수 있음. 해결책 2가지(H1에서 실기기 검증):
  1. S25 크롬 `chrome://flags` → *Insecure origins treated as secure*에 허브 주소 등록 → 앱 설치 가능
  2. 안 되면 "홈 화면에 바로가기 추가"로 사용 (기능 차이 거의 없음)
- 보안: Tailscale에 로그인된 내 기기만 접속 가능 + 허브에 **PIN 로그인** 한 번 더 (같은 Wi-Fi의 다른 사람 대비).

## 3. 허브 소프트웨어

| 구성 | 선택 | 이유 |
|---|---|---|
| 실행 환경 | Termux (F-Droid/GitHub판) | 안드로이드에서 리눅스 프로그램 실행 |
| 웹 서버 | **Node.js, npm 패키지 없이** (`http`, `node:sqlite`, `child_process`) | 설치 실패 위험 최소화. `life/core.js`를 서버에서 그대로 재사용 |
| 데이터 | SQLite 파일 1개 (내장 메모리에 저장, SD 아님) | 빠르고 백업이 쉬움 |
| 썸네일 | `vipsthumbnail`(libvips), 동영상은 `ffmpeg` | 폰에서도 빠른 이미지 처리 |
| 사진 날짜·위치 | EXIF 읽기 (`exiftool` 또는 JS 파서) | 촬영일 기준 타임라인 |
| LLM | llama.cpp `llama-server` + Qwen 소형 모델 | 폰 CPU에서 가장 빠른 실행기, JSON 출력 강제 기능 |

서버 프로세스 2개: ① Node 허브 서버(8080) ② llama-server(127.0.0.1:8081, 외부 비공개 — 허브 서버만 호출).

## 4. 데이터와 기존 앱 연결

- `finance/index.html`, `life/index.html`은 **저장 위치만 바꾼다** (화면·로직 그대로):
  - GitHub Pages에서 열리면 → 지금처럼 브라우저 저장(독립 실행 유지)
  - 허브에서 열리면 → 허브 API에 저장 (`/api/finance` 문서 단위 저장, `/api/life/:store` 기록 단위 저장)
- 동시 수정 충돌: 저장할 때 버전 번호를 함께 보내고, 다르면 "다른 곳에서 수정됨 — 새로고침" 안내.
- 이전(1회): S25에서 쓰던 데이터가 있으면 각 앱의 백업 파일 내보내기 → 허브 설정 화면에서 가져오기.

## 5. 사진

- **원본은 절대 수정·이동·삭제하지 않는다** (SD는 읽기 전용으로만 사용).
- 색인: 경로, 촬영일(EXIF → 없으면 파일 날짜), 크기, 종류(사진/동영상), GPS 좌표.
- 썸네일 2종: 목록용 320px, 보기용 1600px (WebP 또는 JPEG). 내장 메모리에 저장(사진 10만 장 기준 약 5~8GB 예상).
- 첫 색인은 **밤에 충전 중** 실행. 이후 매일 새벽 새 사진만 추가. 진행률을 화면에 표시.
- 화면: 월별 타임라인(무한 스크롤), 연·월 점프, "N년 전 오늘", 사진 크게 보기(좌우 넘김), 동영상 재생, 원본 내려받기.
- **데이터 절약**: 모바일 데이터일 때는 썸네일만 자동 로드, 원본·동영상은 눌렀을 때만.
- 기록과 연결: 경조사·구매 기록 화면에 "그날 사진" 바로가기 (날짜 기준).
- 이번 범위 제외: 사진 속 사물·얼굴 검색 (폰에서는 너무 무거움 — 나중에 별도 검토).

## 6. 질문·답변 (속도 우선 설계)

핵심: **LLM에게 긴 글을 읽히지 않는다.** 폰 CPU에서 느린 건 "긴 입력을 읽는 단계"이기 때문.

```
질문 ─▶ ① 규칙으로 바로 해석 가능? ──예──▶ 앱 코드가 조회·계산 ─▶ 정해진 문장 틀로 답 (1초 이내)
            │아니오
            ▼
        ② LLM이 질문을 "조회 조건(JSON)"으로 번역만 함 (짧은 출력, 고정 안내문은 캐시)
            ─▶ 앱 코드가 조회·계산 ─▶ 정해진 문장 틀로 답 (목표 5초 이내)
            │ 요약·글쓰기가 필요한 질문이면
            ▼
        ③ LLM이 조회 결과(짧게 압축, 최대 약 600토큰)를 읽고 문장 생성, 글자가 바로바로 나오게 표시 (목표: 첫 글자 5초 이내)
```

- **금액·날짜·합계는 항상 코드가 계산** (LLM은 숫자를 만들지 않음). 답변 아래에 근거 기록·사진을 함께 표시.
- 조회 조건(JSON) 형식: `{ "영역": "경조사|물품|카드|메모|재무|구독|사진", "사람": "", "기간": {"시작":"","끝":""}, "분류": "", "동작": "합계|목록|최근|다음|요약|초안" }`

| 질문 예 | 경로 | 답의 근거 |
|---|---|---|
| 작년에 민수 결혼식 얼마 했지? | ① | 경조사 기록 |
| 이번 달 식비 얼마 썼어? | ① | 재무 거래 |
| 넷플릭스 다음 결제일? | ① | 구독 |
| 청소기 보증 언제까지? | ① | 물품 |
| 작년 추석 사진 보여줘 | ①/② | 사진 날짜 색인 |
| 회사 동기 결혼식 때 사진 | ② | 경조사(관계=직장, 결혼) → 그 날짜 사진 |
| 요즘 돈 어디에 제일 많이 썼어? | ② | 재무 카테고리 합계 |
| 올해 경조사 정리해 줘 | ③ | 경조사 목록 요약 |
| 민수한테 결혼 축하 문자 써 줘 | ③ | 사람·경조사 기록 |
| 요즘 내가 고민하던 것들 묶어 줘 | ③ | 메모 최근 목록 |

- 모델: H0 측정 결과로 결정. 후보 1.5B / 3B / 4B급(4비트). **목표 속도를 만족하는 것 중 가장 큰 모델**.
- 허브가 LLM을 못 쓰는 상태(모델 미설치·과열)면 ①만으로 답하고 "자세한 답변은 지금 쓸 수 없음" 표시.

## 7. 상시 운영·백업

- 노트20 설정: **배터리 보호(85%)**, Termux·Tailscale **절전 예외**, 화면 꺼짐 상태 유지, 자동 업데이트로 인한 재부팅 대비.
- 재부팅 시 자동 시작: Termux:Boot + `termux-wake-lock`.
- 과열 보호: 배터리 온도가 높으면 썸네일 작업·LLM 일시 중지.
- 백업:
  - 매일 새벽: 데이터 전체를 SD 카드 `Hub-backup/` 폴더에 날짜별 저장(30일 보관).
  - 매월: 홈 화면에 "백업 파일 내려받기" 알림 → S25나 PC에 보관.
  - **사진 원본(SD) 자체의 백업은 별도로 필요** (PC·외장하드 1회 복사 권장 — SD 고장 시 복구 불가).

## 8. 속도 목표

| 항목 | 목표 (집 Wi-Fi 기준) |
|---|---|
| 화면 열기 | 1초 이내 |
| 사진 목록 스크롤 | 끊김 없음 (썸네일 미리 생성) |
| 질문 ① | 1초 이내 |
| 질문 ② | 5초 이내 |
| 질문 ③ | 첫 글자 5초 이내 |

모바일 데이터에서는 통신 상태만큼 느려질 수 있음. **LLM 속도는 H0 실측 전 추정치**이며, 측정 결과에 따라 모델 크기·질문 경로를 조정한다.

## 9. 개발 단계

| 단계 | 누가 | 내용 | 완료 기준 |
|---|---|---|---|
| **H0** | 사용자 (`hub/H0-GUIDE.md` 따라 하기) | 노트20 기초 세팅, Tailscale 연결, LLM 속도 측정, SD 사진 경로·개수 확인 | S25에서 모바일 데이터로 노트20 LLM 대화 화면 접속, 측정값 공유 |
| H1 | Claude | 허브 서버 뼈대, PIN 로그인, finance·life 저장 위치 전환, 데이터 이전 | S25에서 허브 주소로 재무·기록 입력 → 새로고침·다른 기기에서도 보임 |
| H2 | Claude | 사진 색인·썸네일·타임라인 | 테스트 사진 1,000장 색인, 스크롤 끊김 없음 |
| H3 | Claude | 질문 경로 ① (전 영역) | 위 표의 ① 질문들이 1초 이내 정답 |
| H4 | Claude | 질문 경로 ②③ + 모델 선택 | 위 표 전체 질문 정상 답변, 근거 표시 |
| H5 | Claude + 사용자 | 자동 시작, 백업, 과열 보호, 노트20 실설치 | 노트20 재부팅 후 자동 복구, 새벽 백업 파일 생성 |

H1~H4는 개발 환경(PC/클라우드)에서 만들고 테스트한 뒤, H5에서 노트20에 설치한다.
