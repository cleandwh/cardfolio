# 개인 비서 (라이프 기록 + 로컬 LLM) — 설계서

비업무 개인사(카드·구매 물품·경조사·생각/메모)를 기록하고, 모바일에서 검색·질문하는 개인 비서.
**과금 0원**, 개인 데이터는 내 기기 밖(외부 서비스)으로 나가지 않음.

- 1부: 기록 앱 — `life/index.html` (GitHub Pages: https://cleandwh.github.io/cardfolio/life/), LLM 없이 완결
- 2부: LLM 서버 — 안 쓰는 갤럭시 폰(Termux + Qwen), 메인 폰에서 Tailscale로 접속

> **변경(2026-10-26):** 저장 위치와 LLM 연결은 `hub/DESIGN.md`(노트20 허브 구조)를 따른다. 이 문서의 2장(기록 종류·화면)은 유효, 1장 구조도와 3장(LLM 연결)은 대체됨.

---

## 1. 전체 구조

```
[메인 폰 S25: 기록 앱(PWA)]                     [서버 폰: 노트20 울트라]
 IndexedDB에 모든 기록 저장 (원본)                 Termux + llama.cpp(또는 Ollama) + Qwen
 ① 질문 입력                                       무상태(stateless): 기록을 저장하지 않음
 ② 앱이 기록에서 관련 항목 검색 ──(Tailscale)──→  ③ "질문 + 관련 기록"으로 답변 생성
 ⑤ 답변 표시 + 근거 기록 링크  ←───────────────  ④ 답변 반환
```

원칙:
- **기록의 원본은 메인 폰.** 서버 폰이 꺼져 있어도 입력·검색·통계는 전부 동작.
- **숫자(금액·날짜·합계)는 앱이 계산**해서 LLM에 넘긴다. LLM은 질문 해석과 문장 정리만 담당 → 소형 모델의 계산 실수 방지.
- 답변에는 항상 근거 기록을 함께 표시 (틀렸는지 바로 확인 가능).

## 2. 기록 종류 (1부)

| 종류 | 필드 | 주요 기능 |
|---|---|---|
| 경조사 | 날짜, 사람, 관계(가족/친구/직장 등), 행사(결혼/부고/돌/개업 등), 방향(보냄/받음), 금액, 방식(현금/계좌/선물), 메모 | 사람별 주고받은 합계·차액, 다가오는 행사, "이 사람에게 얼마 했었지" |
| 구매 물품 | 품명, 구매일, 가격, 구매처, 결제카드, 보증 만료일, A/S 연락처, 영수증 사진, 메모 | 보증 만료 임박 알림, 카테고리별 지출 |
| 카드 | 카드명, 연회비, 갱신월, 메모 (+ 재무 대시보드 백업 JSON 가져오기) | 연회비 갱신 알림 |
| 메모·생각 | 날짜, 제목, 본문, 태그 | 전문 검색, 태그 모아보기 |
| 사람(공통) | 이름, 관계, 생일, 메모 | 경조사·메모를 사람 기준으로 묶어 보기 |

- 저장: **IndexedDB** (영수증 사진 때문에 localStorage 불가). 사진은 업로드 시 긴 변 1280px JPEG로 축소.
- 백업: 전체를 하나의 파일(JSON, 사진은 base64 포함)로 내보내기/가져오기. **월 1회 백업 알림** (폰 분실·초기화 대비).
- 검색(LLM 없이): 모든 기록의 텍스트를 대상으로 한 통합 검색 + 종류별 필터 + 기간 필터.
- PWA: manifest + service worker → 홈 화면 설치, 오프라인 동작.

## 3. LLM 연결 (2부)

### 3.1 서버 폰
- 기기: **노트20 울트라** (RAM 12GB, 국내판 스냅드래곤 865+) — 3대 중 가장 여유 있음. S20+/S20은 예비.
- 모델: Qwen 계열 **3B~4B급 4비트 양자화**로 시작 → 속도 괜찮으면 7B~8B급 시도. (구현 시점의 최신 Qwen 소형 모델 중 한국어 품질로 선택)
- 실행: Termux(F-Droid/GitHub판, Play 스토어판은 구버전) + llama.cpp `llama-server` (OpenAI 호환 API).
- 상시 운영: 충전기 연결 + **배터리 보호(85% 충전 제한) 켜기**, 절전 예외 설정, Termux wake-lock.
- 통신: 서버 폰·메인 폰 모두 Tailscale 앱 설치 → **Wi-Fi 없이 모바일 데이터만으로도 연결**. 텍스트만 오가서 데이터 사용량은 미미.

### 3.2 기술 위험: HTTPS 혼합 콘텐츠
기록 앱은 https(GitHub Pages)인데 서버 폰은 http → 브라우저가 차단한다. 구현 시 실기기에서 아래 순서로 검증:
1. 서버 폰에서 Tailscale 인증서로 HTTPS 제공 (가능 여부 확인)
2. 안 되면 서버 폰 앞단에 HTTPS 리버스 프록시
3. 그래도 안 되면 대안: 서버 폰이 기록 앱까지 직접 제공 (단, 그 경우 원본 위치 재설계 필요)

### 3.3 질문 처리 흐름
1. 질문에서 기간·사람·종류 키워드 추출 (앱의 규칙 기반)
2. 관련 기록 상위 20건 + 앱이 계산한 합계를 프롬프트에 넣음
3. 시스템 프롬프트: "주어진 기록에만 근거해 한국어로 짧게 답할 것. 기록에 없으면 모른다고 답할 것."
4. 서버 미연결 시: "비서 오프라인 — 검색 결과만 표시"로 자연스럽게 대체

## 4. 개발 단계

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| L1 | 기록 앱 뼈대, 경조사·사람 기록, 백업 | 경조사 입력 후 새로고침·오프라인에서도 유지, 사람별 주고받은 합계 표시 |
| L2 | 구매 물품(사진)·카드·메모, 통합 검색, 알림 배지 | 보증 만료 30일 이내 물품이 홈에 표시 |
| L3 | PWA 설치·오프라인, 재무 대시보드 백업 가져오기 | 메인 폰 홈 화면 설치 후 비행기 모드에서 동작 |
| S1 | 서버 폰 세팅 가이드 (한국어, 화면 순서대로) | 메인 폰 브라우저에서 모바일 데이터로 서버 응답 확인 |
| S2 | 기록 앱 ↔ LLM 연결, 근거 표시 | "작년에 ○○에게 얼마 했어?"에 정확한 금액 + 근거 기록 표시 |

## 5. 사용자 확인 사항
- 메인 폰: 갤럭시 S25 (확정)
- 서버 폰(노트20 울트라)에 개통 회선 데이터 요금제가 있는지 (서버 폰은 Wi-Fi 있으면 Wi-Fi 사용이 더 안정적)
